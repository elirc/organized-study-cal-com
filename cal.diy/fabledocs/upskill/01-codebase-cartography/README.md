# 01 · Codebase Cartography

The map. Before you can change or critique Cal.diy, you need to know its shape, its vocabulary, and how its real flows move. This module is the foundation the rest of the curriculum builds on.

Read in order:
1. [01-system-map.md](01-system-map.md) — monorepo shape, ownership, public vs. private surfaces.
2. [02-file-reading-order.md](02-file-reading-order.md) — the 25 files to open, in order, split by level.
3. [03-domain-glossary.md](03-domain-glossary.md) — scheduling nouns and where they live in code.
4. [04-runtime-and-tooling-map.md](04-runtime-and-tooling-map.md) — package manager, build, test, runtime boundaries.
5. [05-key-flows.md](05-key-flows.md) — **the centerpiece**: seven flows traced end to end, reused everywhere else.

If you only read one file in this module, read [05-key-flows.md](05-key-flows.md). Everything downstream (patterns, tickets, interview cards) references those seven flows.
